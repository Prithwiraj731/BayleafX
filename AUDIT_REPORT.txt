[SEC-01] HIGH SEVERITY: Vulnerabilities in Bundled PostCSS / Next.js Dependencies
- Advisory IDs: GHSA-r28c-9q8g-f849, GHSA-6g55-p6wh-862q, GHSA-fxqj-rqcc-2cmp, GHSA-qx2v-qp2m-jg93
- Component: next (15.5.25) -> postcss (<=8.5.22)
- CVSS Score: 7.5 (High)
- Description:
  The PostCSS version packaged within the current dependencies is vulnerable to:
  1. Path Traversal in Previous Source Map Auto-Loading (sourceMappingURL),
     which can lead to arbitrary file disclosure (.map files).
  2. Information disclosure via attacker-controlled CSS comments.
  3. Potential XSS via unescaped </style> tags in CSS stringify output.
- Impact:
  Potential exposure of source code maps and styles manipulation.
- Recommended Remediation:
  Add an `overrides` or `resolutions` entry in package.json to force PostCSS
  >= 8.5.23 or run `npm update next` / patch dependency tree.

[SEC-02] MEDIUM SEVERITY: Missing HTTP Security Headers & Framework Fingerprinting
- File: next.config.ts (Line 3)
- Description:
  The Next.js configuration is completely empty (`const nextConfig: NextConfig = {};`).
  As a result:
  1. Next.js sends the `X-Powered-By: Next.js` HTTP response header, revealing the
     underlying framework and version to reconnaissance tools.
  2. Critical security headers are absent:
     - Content-Security-Policy (CSP): Prevents XSS, unauthorized script execution.
     - X-Frame-Options: DENY: Prevents Clickjacking attacks (embedding the site
       inside malicious iframes).
     - X-Content-Type-Options: nosniff: Prevents MIME-type sniffing attacks.
     - Referrer-Policy: strict-origin-when-cross-origin: Prevents leakage of internal
       paths in the HTTP Referer header.
     - Permissions-Policy: Restricts camera, microphone, geolocation access.
     - Strict-Transport-Security (HSTS): Enforces HTTPS connections.
- Recommended Remediation:
  Add `poweredByHeader: false` and a `headers()` async function in next.config.ts
  to inject modern security headers across all routes.

[SEC-03] MEDIUM SEVERITY: Plaintext GitHub Personal Access Token in Local Git Config
- File: .git/config
- Description:
  The GitHub Classic Token (`ghp_...`) is embedded directly in the repository's
  push URL inside `.git/config`:
  `remote.origin.pushurl=https://ghp_...B@github.com/bayleafxtechnologies-boop/BayleafX.git`
- Impact:
  Any developer, tool, script, or local backup that reads `.git/config` has full
  access to this token, which grants full write privileges to all GitHub
  repositories under the user's account.
- Recommended Remediation:
  Store authentication in the Windows Credential Manager or GitHub CLI (`gh auth`),
  or use a read/write deploy key specific only to the BayleafX repository, rather
  than a global account-wide personal access token in plain text.

[SEC-04] MEDIUM SEVERITY: Contact Form Silent Data Loss & Lack of Input Validation
- File: src/components/sections/contact.tsx (Lines 21-25, 120-157)
- Description:
  When a visitor submits the contact form:
  ```typescript
  const handleSubmit = (e: React.FormEvent) => {
    e.preventDefault();
    if (!formData.name || !formData.email || !formData.message) return;
    setSubmitted(true);
  };
  ```
  The handler does NOT send any email, does NOT trigger any API route, and does NOT
  store the submission in a database. It simply toggles local React state:
  "Message received. Thank you, Sarah Chen. We will review your project details and get in touch within 24 hours."
- Impact:
  1. Business Critical: Potential enterprise clients submitting project inquiries
     believe their message was delivered, but it is instantly lost on page refresh.
  2. Security: The inputs lack length constraints (`maxLength`), allowing
     excessive text buffers to be held in client memory.
- Recommended Remediation:
  Implement a Next.js Server Action or API route (/api/contact) connected to Resend,
  Nodemailer, SendGrid, or a webhook (or directly open a pre-filled WhatsApp / mailto
  link as a reliable fallback).

[BUG-01] HIGH: Broken Anchor Navigation from Legal Subpages (Footer & Mobile Menu)
- Files:
  - src/components/layout/footer.tsx (Lines 39-48)
  - src/components/layout/navbar.tsx (Lines 35-44)
- Description:
  In `footer.tsx`, the navigation links use relative anchor tags:
  `href="#services"`, `href="#differentiators"`, `href="#metrics"`, `href="#process"`,
  `href="#testimonials"`, `href="#contact"`.
  The Footer component is rendered on EVERY page, including `/privacy`, `/terms`,
  `/cookies`, and `/refunds`.
  When a visitor on `https://www.bayleafx.com/privacy` clicks "Services" in the footer,
  the browser navigates to `https://www.bayleafx.com/privacy#services`.
  Because that section does not exist on legal pages, nothing happens and the user
  remains stuck on the legal page.
- Recommended Remediation:
  Update links to root-relative hash paths:
  `href="/#services"`, `href="/#differentiators"`, etc.

[BUG-02] MEDIUM: Logo Link Inconsistency & Unnecessary Hash Jump
- File: src/components/layout/navbar.tsx (Line 60)
- Description:
  The Navbar component passes `href="#"` to the Logo: `<Logo href="#" />`.
  Clicking the logo appends `#` to the browser URL and alters scroll position
  without a clean page reset. In contrast, `legal-layout.tsx` passes `<Logo href="/" />`.
- Recommended Remediation:
  Change `<Logo href="#" />` in `navbar.tsx` to `<Logo href="/" />` (or default to `/`
  inside `logo.tsx`).

[BUG-03] LOW: Unclickable "Explore capabilities" CTA in Services Cards
- File: src/components/sections/services.tsx (Lines 76-79)
- Description:
  Each of the three service cards displays an interactive-looking footer:
  ```tsx
  <div className="mt-7 pt-4 border-t border-slate-100 flex items-center justify-between text-xs font-semibold text-[#1B4332] group-hover:text-[#2D6A4F]">
    <span>Explore capabilities</span>
    <ArrowUpRight className="h-3.5 w-3.5 transition-transform group-hover:translate-x-0.5 group-hover:-translate-y-0.5" />
  </div>
  ```
  It has hover animations and an external arrow icon, inviting the user to click.
  However, it is a plain `<div>` with no `onClick`, no `href`, no cursor pointer,
  and no interactive role.
- Recommended Remediation:
  Either connect it to smoothly scroll to `#contact` with pre-filled interest, or
  link to the contact section with a semantic button/anchor.

[BUG-04] LOW: Deprecated DOM API & Inaccurate TOC Offset in Legal Layout
- File: src/components/layout/legal-layout.tsx (Lines 47-48, 66)
- Description:
  1. Line 66 uses `window.pageYOffset`, which is deprecated across modern browser
     standards in favor of `window.scrollY`.
  2. Line 47 uses `el.offsetTop`. In CSS, `offsetTop` is relative to the nearest
     `offsetParent` element, NOT the document root. If any parent container has
     relative or absolute positioning, the scroll calculation drifts, causing the
     active Table of Contents indicator to highlight the wrong section.
- Recommended Remediation:
  Use `element.getBoundingClientRect().top + window.scrollY` and replace
  `window.pageYOffset` with `window.scrollY`.

[BUG-05] LOW: Missing Form AutoComplete & Input Identifiers
- File: src/components/sections/contact.tsx (Lines 121-145)
- Description:
  The input elements rely on generated labels but omit standard HTML `autoComplete`
  and explicit `name` attributes:
  - Name: Missing `autoComplete="name"` and `name="name"`
  - Email: Missing `autoComplete="email"` and `name="email"`
- Impact:
  Mobile devices and browser password/contact managers cannot auto-fill user details.
- Recommended Remediation:
  Pass explicit `id`, `name`, and `autoComplete` props to `Input` and `Textarea`.

3. PERFORMANCE & ASSET BLOAT (CRITICAL CORE WEB VITALS)
================================================================================

[PERF-01] CRITICAL: 5.37 MB Uncompressed Favicon & App Icons
- Files:
  - public/tab-logo.png (5,372,428 bytes — 5.37 MB)
  - src/app/apple-icon.png (5,372,428 bytes — 5.37 MB)
  - src/app/icon.png (5,372,428 bytes — 5.37 MB)
- In `src/app/layout.tsx`:
  ```typescript
  icons: {
    icon: [{ url: '/tab-logo.png', type: 'image/png' }, { url: '/favicon.ico', sizes: 'any' }],
    apple: [{ url: '/tab-logo.png', type: 'image/png' }],
    shortcut: ['/tab-logo.png'],
  }
  ```
- Impact:
  This is a critical performance bug. Every single browser that visits `bayleafx.com`
  attempts to download a 5.37 Megabyte high-resolution image just for a 32x32 tab icon!
  On mobile 4G/3G connections, this adds several seconds of network latency, burns
  user mobile data, and degrades Google PageSpeed / Lighthouse scores significantly.
- Recommended Remediation:
  Resize and optimize `tab-logo.png`, `icon.png`, and `apple-icon.png` to proper
  standard favicon dimensions:
  - 32x32 / 48x48 for favicon (~5-15 KB)
  - 180x180 for apple-touch-icon (~30-50 KB)
  Total savings: > 5.3 MB per page load.

[PERF-03] LOW: Dead Code & Unused Client Bundle in Hero Section

4. ACCESSIBILITY (A11Y) & SEO DEFICIENCIES
================================================================================

[A11Y-01] LOW: Missing Accessible Name on Star Ratings
- File: src/components/sections/testimonials.tsx (Lines 42-45)
- Description:
  The 5 star icons are mapped without an enclosing container `aria-label="5 out of 5 stars"`.
  Screen reader users hear five empty SVG icons instead of the actual rating value.
- Recommended Remediation:
  Add `role="img" aria-label="5 out of 5 stars"` on the star container.

[SEO-01] LOW: Dynamic Sitemap Timestamp
- File: src/app/sitemap.ts (Line 5)
- Description:
  `const currentDate = new Date();` generates a new timestamp on every sitemap request.
  Search engine crawlers (Googlebot) see every static legal page marked as modified
  at the current minute, which reduces crawl efficiency and trust in `lastModified` headers.
- Recommended Remediation:
  Use a stable ISO date string for static/legal pages (e.g. '2026-09-18') and update
  only when page content actually changes.
